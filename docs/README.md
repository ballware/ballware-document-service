# ballware document service — documentation

This folder documents the document service from the backend side: its HTTP API surface,
request/response payloads, document model, tenancy and authorization behavior, designer and
datasource integration, background jobs, and the OpenAPI snapshots the pages are derived from.

> Scope note: this is the **backend view** of the service. Setup, configuration and deployment
> live in the repository [README.md](../README.md). The frontend metadata consumption contract
> (how select-list and editing payloads are interpreted by the UI framework) lives in
> `ballware-angular/docs/metadata` and is not duplicated here.

## Quick facts

- Two OpenAPI documents per service: `document` ("ballware document user API", 44 paths,
  9 schemas) and `service` ("ballware document service API", 9 paths, 4 schemas), OpenAPI `3.0.4`
  (`src/Ballware.Document.Service/Startup.cs:128-138`).
- Committed OpenAPI snapshots: [openapi/document.json](openapi/document.json),
  [openapi/service.json](openapi/service.json), generated by
  [openapi/fetch-spec.sh](openapi/fetch-spec.sh) with Swashbuckle CLI `10.3.0`.
- Swagger UI: `http://localhost:5004/swagger` (PKCE-enabled, `Startup.cs:241-253`); raw documents
  at `/swagger/document/swagger.json` and `/swagger/service/swagger.json`.
- Development ports: `http://localhost:5004` (Service host, API + Swagger + Quartz) and
  `http://localhost:5005` (App host, Blazor designer/viewer) — see the repository `README.md`.
- Authentication: JWT bearer against an OIDC issuer; authorization by scope → policy
  (`documentApi` for all `/document/**` user operations, `serviceApi` for Service API
  operations, `src/Ballware.Document.Hosting/ServiceCollectionExtensions.cs:324-326`).
- Security scheme: `oidc` with `openIdConnectUrl = <Authority>/.well-known/openid-configuration`
  (`Startup.cs:142-146`).
- JSON bodies are PascalCase (`Startup.cs:85-93`).
- Request culture is pinned to `de-DE` (`Startup.cs:207-212`).

## Request flow

```text
client (browser / SPA / other ballware service)
  |  Authorization: Bearer <token>
  v
ASP.NET Core routing + JWT bearer authentication       Startup.cs:196-204
  |  scope claim -> policy "documentApi" / "serviceApi"
  v
endpoint handler                                       Startup.cs:218-230
  |  select-list / user-specific handlers read the
  |  tenant from the "tenant" claim; service handlers
  |  take explicit {tenantId} path segments
  |
  |  generic editing handlers resolve right candidates
  |  meta.<entity>.<right> via the rights checker     (Jint scripts from the Meta Service)
  v
repository / EF Core store                             tenant-scoped, postgres or mssql
  |
  +--> Meta / Storage / Generic / ML service clients   client-credentials token management
  +--> Quartz scheduler                                durable jobs: import, updatedatasources,
  |                                                    trigger, frequency
  v
DevExpress reporting core                              document rendering for mail/PDF
```

## Regenerating the OpenAPI snapshots

All API pages here are derived from the committed snapshots. After endpoint changes, run
[openapi/fetch-spec.sh](openapi/fetch-spec.sh) and re-check the counts above; see
[openapi/README.md](openapi/README.md).
